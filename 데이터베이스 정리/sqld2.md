# 📘 오늘 공부한 내용 정리

## 1. 정규형 (1NF ~ 3NF)

### ✔ 1정규형(1NF)
- 모든 속성은 **원자값(쪼갤 수 없는 값)** 이어야 함.
- 한 셀에 여러 값 넣으면 안 됨.
- 예) 전화번호 여러 개 → 행으로 분리해야 함.

---

### ✔ 2정규형(2NF)
- **부분 함수 종속 제거**  
- 기본키가 여러 컬럼(복합키)일 때, 키의 일부에만 종속되는 속성을 분리.
- 예) (학생, 과목)에서 “학생이름”은 학생에만 종속 → 분리해야 함.

---

### ✔ 3정규형(3NF)
- **이행적 종속 제거**  
- 비키(Non-key) 속성이 다른 비키에 의존하면 분리.
- 예) 학생 → 학과 → 학과장 → 학과장은 학과에 종속 → 따로 분리.

---

## 2. 속성 종류

### ✔ 일반 속성
- 엔티티가 가진 **일반적인 정보**  
- 식별 목적 아님  
- 예) 학생 이름, 주소, 전공

### ✔ 식별자 속성
- 엔티티를 유일하게 구분  
- 예) 학번(Primary Key)

### ✔ 보조 식별자
- PK는 아니지만 엔티티를 구분할 수 있는 후보키  
- 예) 주민번호(보안 문제로 사용은 지양)

### ✔ 설계 속성
- 실제 업무에는 없지만, 시스템 설계/운영을 위해 추가
- 예) 등록일(created_at), 수정일(updated_at)

### ✔ 파생 속성
- 다른 속성으로부터 **계산해서 얻는 값**
- DB에 저장하지 않아도 됨
- 예)
  - 나이 = 현재날짜 - 생년월일  
  - 학년 = 현재년도 - 입학년도 + 1  
  - 총 이수 학점 = 과목 학점 합계  

---

## 3. 기본키(PK)
- 기본키는 엔티티를 유일하게 식별하는 값.
- **학생 엔티티에서는 학번이 일반적인 PK.**
- 이름, 전화번호는 중복·변경 가능하기 때문에 PK가 될 수 없음.

---

## 4. 학생 엔터티의 파생 속성 예시
| 파생 속성 | 계산 근거 |
|-----------|-----------|
| 나이 | 생년월일 |
| 학년 | 입학년도 |
| 재학기간 | 입학일 |
| 만 나이 | 생년월일 |
| 총 이수 학점 | 과목 학점 합계 |

---

## 📌 오늘 핵심 요약
- 정규화는 데이터 구조의 **안정성과 무결성**을 높이는 과정.  
- 성능은 상황에 따라 좋아지기도, 복잡해지기도 함.  
- 속성은 일반/식별자/설계/파생 등으로 구분해 설계 품질을 높임.  
- 학생 엔터티에서 PK는 **학번**, 파생 속성은 **나이·학년·총학점** 등.
