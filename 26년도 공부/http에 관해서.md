# HTTP (HyperText Transfer Protocol) 핵심 정리

## 1. HTTP란?
**HTTP(HyperText Transfer Protocol)**는 웹상에서 클라이언트(주로 웹 브라우저)와 서버가 데이터를 주고받기 위해 사용하는 통신 규약(프로토콜)이다. 초기에는 HTML 문서(HyperText)를 전송하기 위해 만들어졌으나, 현재는 JSON, 이미지, 영상, 오디오 등 거의 모든 형태의 데이터를 전송하는 데 사용됨.



---

## 2. HTTP의 3가지 주요 특징

* **클라이언트-서버 구조 (Client-Server Architecture):** 클라이언트가 서버에 **요청(Request)**을 보내면, 서버는 그에 대한 **응답(Response)**을 보낸다. 클라이언트와 서버가 각자의 역할에 집중할 수 있도록 분리되어 있다.
* **무상태성 (Stateless):** 서버는 클라이언트의 이전 상태(요청)를 기억하지 않는다. 서버의 확장성이 높아진다는 장점이 있지만, 로그인이 필요한 서비스 등에서는 상태 유지를 위해 별도의 기술(쿠키, 세션, 토큰 등)이 필요하다.
* **비연결성 (Connectionless):** 요청을 주고 응답을 받으면 서버와 클라이언트의 연결을 끊는다. 서버 자원을 효율적으로 사용할 수 있지만, 매번 새로운 연결을 맺어야 하는 오버헤드가 발생한다. (현재는 `Keep-Alive` 기능을 통해 일정 시간 동안 연결을 유지하여 이를 보완한다.)

---

## 3. HTTP 메시지 구조

HTTP 통신은 텍스트 기반의 메시지를 통해 이루어지며, 크게 **요청(Request)** 메시지와 **응답(Response)** 메시지로 나뉜다.

### 요청 메시지 (Request Message)
1.  **시작 줄 (Start Line):** HTTP 메서드, 요청 대상(URL), HTTP 버전 (예: `GET /index.html HTTP/1.1`)
2.  **헤더 (Headers):** 요청에 대한 부가 정보 (예: 브라우저 정보, 데이터 타입 등)
3.  **본문 (Body):** 서버로 전송할 실제 데이터 (GET 요청 시에는 보통 비어 있음)

### 응답 메시지 (Response Message)
1.  **상태 줄 (Status Line):** HTTP 버전, 상태 코드, 상태 메시지 (예: `HTTP/1.1 200 OK`)
2.  **헤더 (Headers):** 응답에 대한 부가 정보 (예: 데이터 크기, 서버 정보 등)
3.  **본문 (Body):** 클라이언트에게 전송할 실제 데이터 (HTML, JSON 등)

## 4. 주요 HTTP 메서드

클라이언트가 서버에게 **'무엇을 할 것인지'** 목적을 알리는 역할을 한다.

| 메서드 | 역할 | 특징 |
| :--- | :--- | :--- |
| **GET** | 리소스 조회 (Read) | 서버의 데이터를 가져올 때 사용. 요청 본문을 사용하지 않음. |
| **POST** | 데이터 생성/처리 (Create) | 서버에 데이터를 보내서 새로운 리소스를 생성하거나 처리할 때 사용. |
| **PUT** | 리소스 전체 수정 (Update) | 리소스가 있으면 대체하고, 없으면 새로 생성함. |
| **PATCH** | 리소스 부분 수정 (Update) | 리소스의 특정 부분만 수정할 때 사용. |
| **DELETE**| 리소스 삭제 (Delete) | 서버의 리소스를 삭제할 때 사용. |

---

## 5. 주요 HTTP 상태 코드

서버가 클라이언트의 요청을 어떻게 처리했는지 알려주는 세 자리 숫자다.

| 코드 대역 | 의미 | 대표적인 예시 |
| :--- | :--- | :--- |
| **2xx** | **성공 (Successful)** | `200 OK` (성공), `201 Created` (생성됨) |
| **3xx** | **리다이렉션 (Redirection)** | `301 Moved Permanently` (영구 이동), `302 Found` (임시 이동) |
| **4xx** | **클라이언트 오류 (Client Error)** | `400 Bad Request` (잘못된 요청), `401 Unauthorized` (인증 안 됨), `403 Forbidden` (권한 없음), `404 Not Found` (찾을 수 없음) |
| **5xx** | **서버 오류 (Server Error)** | `500 Internal Server Error` (서버 내부 오류), `503 Service Unavailable` (서비스 이용 불가) |

---

## 6. HTTP의 진화 (버전별 특징)

* **HTTP/1.1:** 현재 가장 많이 사용되는 기본 프로토콜. 연결 유지(Keep-Alive) 기능 추가.
* **HTTP/2:** HTTP/1.1의 성능(속도)을 개선. 멀티플렉싱(Multiplexing) 기술로 여러 요청과 응답을 동시에 처리.
* **HTTP/3:** TCP 대신 UDP 기반의 QUIC 프로토콜을 사용하여 연결 설정 시간을 획기적으로 단축하고 속도를 개선.
* **HTTPS (HTTP Secure):** HTTP에 데이터 암호화(SSL/TLS)를 추가하여 보안을 강화한 프로토콜.
